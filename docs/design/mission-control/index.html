The one idea

Sort by who is blocked, not by what is loud. The screen answers four questions top to bottom: what needs me, what is progressing, what is waiting and on what, and what is ready to review. A live transcript feed is noisy and makes every tile look equally urgent, so it moves into the inspector where you look at it on purpose.

Control and ease at the same time

EaseControl
One primary action per row, named after the decision (“Review request”, “Answer”, “Review result”).Every action is scoped and reversible in the inspector: allow exactly these files, this turn only, or deny with a note. No “approve all”.
Groups are fixed and the inspector never moves, so the layout is learned once.Stop, steer, retry, open worktree, open session are always in the same bar; unavailable ones are disabled with a reason.
Status is a word plus one reason line, never a raw lifecycle enum.Identity (task, attempt, session), branch, runtime and budget are one row down in Overview; raw JSON is a collapsed diagnostics drawer.
Incoming events never move focus or the row under the pointer.Keyboard covers everything: J/K, Enter, O, I, X, A, D, ⌘K.
Nothing needs you → a calm empty state, not an empty grid.Multi-select offers only the actions valid for every selected item.

Row anatomy

  • State icon carries the only hue on the row: warning for anything blocked on a human, success for live progress, destructive for failed/stalled, info for review, neutral for waiting and terminal states.
  • Title + breadcrumb: task title, then project › parent mission › harness mark and role. The harness hue lives on the small square only; the name stays achromatic.
  • State + reason: bold word, then one line that says what would unblock it. A heartbeat is never shown as progress.
  • Age with a label that says what the number means: waiting, active, queued, silent, reported, ended. Terminal items stop counting.
  • Primary action and a ⋯ menu for the rest.

What the read model must provide

Everything on these screens comes from the typed fleet projection in #576: lifecycle, wait kind and responsible actor, failure class, completion verdict (worker claim, verification, adoption as three separate facts), stable task/attempt identity, freshness metadata, and an action-eligibility list. The frontend only derives labels. Nothing here needs transcript events for row correctness.

Deliberately not in v1

  • Grid and graph modes (kept as a toggle stub in the top bar; ship after list testing).
  • Percent complete, ETA, cost analytics.
  • Worktree cleanup inside Mission Control (link to the storage manager from #574).
