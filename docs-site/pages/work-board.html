work, memory & learning

The work board

A briefing of activity from your connected integrations in the past 24 hours: Slack, GitHub, Gmail, Linear, and Notion.

Recent integration activity

Work shows one list, newest activity first. Each item has a source and account label, a source timestamp, a short summary, and a link to the original when available. Local Bridge checks, approvals, worker queues, and workspace drift stay off this screen.

The board is a briefing, not an exhaustive activity export. Each run can contribute up to 12 summaries, and the board shows up to 100 recent saved items. The status line tells you which tools were actually read and which could not be reached.

Open and set up Work

Go to Settings → Work briefing → Open Work. Choose a supported briefing model and the connected tools it should read. You can also reach those settings through Set up integrations on an unconfigured board.

Opening Work reads the saved board. Clicking Refresh runs a new integration briefing when configured. The button is disabled while a run is active. The browser preview has no live connectors and shows an empty board instead of sample work.

What “past 24 hours” means

The window follows the activity timestamp reported by the source item, such as a Slack message time or a GitHub issue update. Reading an old item again does not make it recent. Missing, invalid, future, and expired source dates are excluded.

The briefing searches using explicit UTC bounds and reads individual items for evidence. A date on a multi-item search response cannot make every result recent. Existing saved items without source dates remain hidden until a dated source read replaces them.

The open board checks its clock every 30 seconds. Expired items disappear even without another refresh. A failed refresh keeps only previously read items still within the window and reports the failure.

Read-only briefings and source links

A briefing reads the selected integrations through the existing provider permission gate. It cannot run shell commands, access local files, or write to connected tools. The model summarizes returned data; it cannot supply its own source timestamp, identity, or link.

Source links open the original item and are checked again before opening. The board does not start local tasks, send messages, change issues, or route summaries into workspaces.

Refresh settings

Settings controls optional scheduled refreshes and refresh on focus. Both are off by default; manual refresh is available after setup. Existing cooldown, lease, and run-budget limits still apply. Use the run status and source coverage to distinguish a completed read from a skipped or failed refresh.
