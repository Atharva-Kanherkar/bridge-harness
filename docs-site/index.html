getting started

What is Bridge

Bridge is a macOS desktop app that runs Codex, Claude Code, and OpenCode against isolated Git worktrees — one interface for supervising multiple coding agents, backed by a policy engine that decides what any of them are allowed to touch.

Three hierarchies, kept separate

The recurring design bug in agent tooling is conflating three things that only look alike: where files live, who's allowed to act, and what was said. Bridge keeps them as three distinct trees.

Workspace tree

Repo → task worktree → worker worktree. Every agent gets its own isolated checkout.

Agent tree

Orchestrator → policy-authorized workers. Delegation is a permission, not a suggestion.

Conversation tree

Immutable forest entries → the active branch. Append-only, forkable, never rewritten.

Forking a conversation does not undo filesystem changes. Ending a session does not discard a worktree. Each tree is managed on its own terms.

What's running underneath

A Rust workspace sits under a thin Tauri shell. bridged owns the data directory and speaks newline-delimited JSON-RPC over a Unix socket — the desktop app is just one client of it.

core concepts

Session forest

Every conversation Bridge has ever had lives in one append-only forest. Nothing is deleted and nothing is rewritten — the forest only ever grows.

Immutable entries

Each entry carries a parent, an event kind, and the visibility rules that decide what gets projected into context. Switching branches, forking a conversation, or resuming after a restart are all just different walks over the same structure.

forest entry 
{
  "id": "evt_9f2c",
  "parent": "evt_8ad1",
  "kind": "assistant_message",
  "visibility": "context",
  "checkpoint": false
}

Compaction and resume

Long conversations get summarized without losing the underlying record. A checkpoint is added, not substituted — the raw entries stay in the forest even after a summary sits in front of them.

Compaction adds a verified checkpoint boundary rather than rewriting events — history stays intact even after it's been summarized.

reference

bridge exec --json

The one-shot entry point for CI: hand it a prompt, get newline-delimited JSON back, no daemon babysitting required.

Example

Every line of output is a complete, independently-parseable JSON object — pipe it straight into jq or a test harness.

bash 
$ bridge exec --json "run the test suite and summarize failures"
{"type":"session_started","session_id":"ses_4c1a"}
{"type":"agent_message","text":"Running `bun run test`…"}
{"type":"result","status":"ok","duration_ms":48213}

Flags

FlagTypeDefaultDescription
--jsonbooleanfalseEmit newline-delimited JSON instead of formatted text
--harnessstringcodexWhich adapter to run: codex, claude, or opencode
--worktreepath—Run against an existing worktree instead of creating one
--timeoutduration10mKill the session if it runs past this

A session killed by --timeout does not clean up its worktree automatically — remove it yourself if you don't need it.
